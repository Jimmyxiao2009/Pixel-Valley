## 0. 仓库现状与技术假设

### 0.1 仓库现状

当前工作区几乎为空（greenfield）。**不存在**可复用的 `src/`、路由、组件库、后端或设计系统。下文出现的路径均为**拟建文件**，不是对已有代码的描述。

### 0.2 技术假设（写入工程，不假装已存在）

| 层 | 假设 |
| --- | --- |
| 客户端 | Web 优先（桌面 ≥1024、平板、移动）。点击 / 触控。不依赖 WASD / 摇杆。 |
| 前端 | Vite + React + TypeScript SPA。地图用 **DOM 场景图**（每个房子/热点是真实可聚焦控件），不用 Canvas 作为主交互层。 |
| 样式 | 原创像素风 CSS + SVG/PNG sprite。禁止 emoji 当正式 UI、禁止通用 SaaS dashboard 风。 |
| 实时 | 在线聊天走 WebSocket；离线留言走 REST 消息存储。同一套 `Conversation` / `Message`。 |
| AI | 全部经后端代理，客户端不直连模型。MVP `MockAIService` 只存在于 API 进程。 |
| 数据 | PostgreSQL 为主存储（PR-12a）。Presence / session：**适配器**（PR-2 内存，PR-12b 可换 Redis，非硬依赖）。对象存储后期再接图片。 |
| 后端 | **Hono + TypeScript**（`apps/api`），领域类型只在 `packages/domain`；`apps/web` 再导出，禁止第二份 `types.ts`。Mock `api.ts` 实现同一接口。 |
| 本地开发 | PR-1 起 Vite 把 `/api` 与 `/ws` **同源反代**到 Hono，Cookie `pv_session` 为 same-site。禁止浏览器直连另一 origin。 |
| 鉴权 | HttpOnly Cookie 会话；MVP 演示账号一键登录。社区层所有写操作取会话居民，禁止 body 里自报 `authorResidentId`。 |
| 无障碍 | 所有点击目标可键盘到达；状态不只靠颜色；`prefers-reduced-motion` 跳过公交/气泡升起。 |
| 语言 | 产品文案简体中文。 |
| 身份 | `Account` 1:1 人类 `Resident`。社区层只认 Resident。AI 无登录。 |

## 1. 概念总结

### 1.1 一句话

像素谷是一座可以住进去的论坛：居民住在自己的房子里发帖，帖子变成房顶气泡，邻里地图负责人和关系，镇中心负责信息和发现，AI 是镇民而不是聊天插件。

### 1.2 世界观

用户不是「账号」，是「居民」。空间分层固定为三层，不可做成开放世界：

```
家（Home）        私密仪式：发帖、房间、个人 AI
  ↓ 出门
邻里（Neighborhood） 关系与存在感：房子、气泡、串门、敲门
  ↓ 公交
镇中心（Town）      效率信息流：热门 / 最新 / 长文 / 闲聊
```

时间感来自「街上谁亮着灯、谁房顶在说话」，不是等级、金币或任务。

### 1.3 与普通论坛的差异（必须守住的记忆点）

| 普通论坛 | 像素谷 |
| --- | --- |
| 头像 + 昵称 | 一栋房子 + 门牌 |
| 发帖按钮在顶栏 | 坐在家里电脑前写一句话 |
| 帖子在时间线列表 | 帖子先出现在房顶气泡，再进入镇中心 |
| 主页是资料卡 | 主页是可进屋的房间 |
| 私信是收件箱 | 在线敲门串门 / 离线留纸条 |
| AI 是侧边机器人 | AI 有房子、气泡、状态，走同一套居民交互 |
| 发现靠频道/推荐流 | 发现分两路：街上逛人，镇上读书看报 |

### 1.4 明确不是什么

- 不是种田 / RPG / 开放世界 / 数值养成。
- 不是 Discord 服务器模拟器。
- 不是「论坛套一层像素皮肤」。若去掉房子和气泡后产品仍能原样运作，说明空间化失败。

### 1.5 体验承诺（给所有角色的对齐句）

> 三秒内能发帖、两击内能读到信息流、随时能回到自己的家。游戏感只做氛围和记忆点，不做操作税。

### 1.6 编号原则（后文 KD 引用此表）

| 编号 | 原则 |
| --- | --- |
| 原则 1 | 像镇子，但不是复杂游戏：不做种田 / 任务链 / 数值养成 / WASD 探索。 |
| 原则 2 | 操作轻量：点击 / 触控为主；动画不得拦截点击。 |
| 原则 3 | 房子就是主页：个人身份必须空间化。 |
| 原则 4 | 帖子必须可见化：发帖后房顶出现气泡。 |
| 原则 5 | AI 是居民：与人类同一套社交对象；禁止悬浮机器人。 |
| 原则 6 | 邻里服务人和关系，镇中心服务内容发现；效率门优先于漫游。 |

## 2. 信息架构

### 2.1 空间结构（产品 IA = 世界 IA）

```
像素谷
├── 家 Home                      /home
│   ├── 电脑 Computer            → 发帖 Composer（模态）
│   ├── 书架 Bookshelf           → 我的帖子 / 简介 / 收藏入口
│   ├── 伙伴坐垫 Companion       → 个人 AI（若有）
│   ├── 门 Door                  → 邻里地图（角色出现在家门口）
│   └── 窗 / 灯                  → 只读状态表现（不单独成页）
│
├── 邻里
│   ├── 我的街 StreetMine        /street          【派生视图】自己视觉居中，不改户籍地块
│   ├── 户籍街 Canonical         /n/:neighborhoodId 【持久地块】House.slotIndex 的真相
│   │   ├── 住户房子（人类）      → PeekCard → 进屋 / 敲门 / 留纸条
│   │   ├── 空地 vacant          → 「这块地还空着」
│   │   ├── 房顶气泡 PostBubble  → PostDetailSheet
│   │   ├── 公交站 overlay       → 乘车；路路挂在站亭，不占 House 行
│   │   └── 道路 / 树
│   └── 邻里街 / 推荐街          /street?slice=neighbors|recommended  分页，非无限地图
│
├── 居民主页 ResidentHome        /r/:residentId
│   ├── 房间场景（与自家同模板）
│   ├── 门牌资料
│   ├── 作品墙 / 最近帖子
│   ├── 书架收藏（P1 只读列表）
│   └── 屋内 AI 伙伴（若主人公开）
│
├── 信箱 Mail                    /mail
│   ├── 会话列表
│   └── 聊天 / 纸条 同一线程
│
└── 镇中心 Town                  /town/:zone
    ├── 广场 Plaza               推荐 / 热门 / 最新
    ├── 公告栏 Board             趋势 / 官方
    ├── 图书馆 Library           长文 / 知识
    └── 咖啡馆 Cafe              短帖 / 闲聊 / 正在发生
```

### 2.2 全局常驻导航（空间隐喻下的效率层）

纯漫游会迷路，也会让回访用户每多点 2 次。**必须常驻轻量导航**，同时保留第一次「出门 / 坐公交」的仪式。

**组件：`WorldNav`（全局 HUD，始终挂载，不随场景缩小或卸载）**

桌面与移动均为底部居中 **4 键**（信箱键自带未读角标，**不再**另放右侧徽章）。高度 56px，点击区 ≥ 44px。

| 键 | 文案 | 路由 | 行为 |
| --- | --- | --- | --- |
| 家 | 回家 | `/home` | 瞬移进屋。若当前已在自家，聚焦电脑。 |
| 邻里 | 上街 | `/street` | 打开**派生「我的街」**，自己视觉居中。 |
| 镇中心 | 去镇上 | `/town/plaza` | **跳过公交动画**（公交是地图里的叙事入口，不是唯一入口）。 |
| 信箱 | 信箱 | 打开 `MailDrawer` | 不改 `worldLocation`；未读角标在此键上。深链 `/mail` 才是独立页。 |

附加：

- 左上 **面包屑**（可点）：
  - 派生我的街：`像素谷 / {homeNeighborhood.name} / 我的街`。中间段进 **户籍街** `/n/{homeNeighborhoodId}`（自己在持久 slot）。
  - 自己的户籍街：`像素谷 / {homeNeighborhood.name}`。
  - 做客户籍街：`像素谷 / {hostStreet.name}`。
  - 进屋：`像素谷 / {street.name} / {nameplate}`。点名牌回户籍街；点街名同上。
- 右上 **自己的状态灯** + 头像门牌 → `SelfStatusMenu`（在线 / 请勿打扰 / 隐私：谁能敲门、谁能留纸条、对他人显示出门）。
- 第一次坐公交：播放 ≤1.2s 过场，可 Skip。之后 `WorldNav` 去镇上不再强迫过场。用户仍可在地图点公交站重温过场。

键盘：`g` 然后 `h` / `n` / `t` / `m` 仅当焦点 **不在** `input/textarea/[contenteditable]` 且 **没有 IME composing** 时生效。Tab 循环热点。

### 2.3 场景 vs 路由映射

| `worldLocation` | 路由 | 场景组件 |
| --- | --- | --- |
| `home` | `/home` | `HomeScene`（主人视角） |
| `street-mine` | `/street` | `NeighborhoodScene mode="mine"`（派生我的街） |
| `neighborhood` | `/n/:neighborhoodId` | `NeighborhoodScene mode="canonical"`（户籍地块） |
| `resident-home` | `/r/:residentId` | `HomeScene`（访客视角 `mode="guest"`） |
| `town` | `/town/:zone` | `TownScene` |
| `mail` | `/mail` | `MailScene` 全页（仅深链 / 刷新） |

`MailDrawer` **不是** `worldLocation`：WorldNav 信箱只设 `mailOpen=true`，保持当前场景。帖子详情、居民卡片、发帖窗、聊天窗同为 overlay（进屋除外）。

### 2.4 功能 IA（非空间）

```
账号 Account  1:1 → 人类 Resident（AI 公共服务无 Account；个人 AI 为 P2 且无登录）
 └─ 居民 Resident (human | ai)
     ├─ 房子 House（人类 1:1 户籍地块；路路无 House）
     ├─ 帖子 Post[]
     ├─ 气泡 Bubble（由最近公开帖派生，不独立编辑）
     ├─ 邻里关系 NeighborEdge（单向 follow；派生街在同户籍填完后才用它补槽）
     ├─ 拜访 Visit（仅后端埋点，主人不可见）
     ├─ 拉黑 Block
     └─ 会话 Conversation[]  （敲门 / 纸条共用）
```

### 2.5 镇中心区域与公共服务型 AI 的锚点

| 区域 | 路由 | 内容职责 | 常驻 AI 居民 |
| --- | --- | --- | --- |
| 广场 | `/town/plaza` | 推荐 / 热门 / 最新 | 向导 **青禾**（新手、镇介绍） |
| 公告栏 | `/town/board` | 趋势话题 / 官方通知 | 编辑 **墨白** |
| 图书馆 | `/town/library` | 长文 / 知识 | 馆长 **南风** |
| 咖啡馆 | `/town/cafe` | 短帖 / 闲聊 | P2：店主 **暖暖**（MVP 可用南风或青禾兼看） |
| 公交站（邻里地图） | overlay | 去镇上 | 站务 **路路** |
| 邻里出生点 | overlay | 第一次出门 | 青禾作为 **全局 overlay** 出现在「我的街」一次，不占户籍 House 行 |

公共服务 AI **只有一条 Resident 记录**，禁止按街区克隆。路路 / 青禾以 overlay 挂到各视图；南风 / 墨白户籍在 **镇心街**（civic neighborhood），镇中心建筑可点到同一 Resident。详见 12.4。

### 2.6 信息层级原则

- **邻里 = people**：谁在、谁写了新帖、谁可以串门。
- **镇中心 = content**：什么值得读，2 次点击内到达信息流。
- **家 = identity + compose**：我是谁、我如何发言。
- 禁止在邻里地图上做无限滚动信息流；禁止在镇中心让角色走来走去找帖子。

### 2.7 邻里双视图（必读，避免把槽位写崩）

存在两套布局，**不可混用 `House.slotIndex`**：

| | 户籍街 Canonical | 我的街 Derived |
| --- | --- | --- |
| 路由 | `/n/:neighborhoodId` | `/street` |
| 槽位来源 | 持久 `NeighborhoodTile` + `House.slotIndex` | 请求时组装，**不写库** |
| 自己在哪 | 仅当自己的户籍在这条街时，出现在**自己的地块**；访客不改别人的街 | **永远**视觉中心（逻辑槽 4） |
| 谁住在街上 | 签到时分到的住户 + 空地 | 同户籍钉在持久槽后与槽 4 对换；邻里/推荐只进剩余空槽；overlay AI |
| 如何打开 | 地图 Tab「{街名}」或面包屑街名 → `/n/{homeNeighborhoodId}` | WorldNav「上街」、家门、回访、wow |
| 拜访陌生人出门 | 停在对方户籍街，镜头对准对方地块 | 「回我的街」才回到派生视图 |
| 点自家房子 | `/home` | `/home`（不是再开一张派生图） |

WorldNav「上街」、自家门、回访默认、首次发帖 wow：**都进派生我的街**（必能看见同户籍邻居）。  
地图 Tab / 面包屑街名：**进自己的户籍街**（自己在持久 slot，如梧桐街槽 4）。  
「去作者家门口」、访客房的门：**都进对方户籍街**。

## 3. 核心用户流程

以下每条均含：触发、步骤、界面、成功标准、失败/空态。角色名用种子居民举例。

### 3.1 用户进入产品后的默认体验

**决策：新用户第一次进室内；之后每次回访落在派生「我的街」（自己居中，同户籍邻居可见）。户籍街经 Tab/面包屑进入，不是默认落点。**

#### A. 首次会话（未完成「第一句话」）

1. `LoginScene` 一键演示登录（会话 Cookie）→ `/home`。
2. `HomeScene`：房间灯光偏暖，电脑热点有缓慢呼吸高亮 + 文案「坐下来，写一句今天想说的话」。
3. 可不发帖，点门出门到 `/street`；若未发帖，房顶无气泡，门口弱提示「回家写一句，街上就会看见你」。
4. 完成首次发帖后，标记 `onboarding.firstPostAt`，**仅此一次**自动开门切到 `/street`，自己居中，气泡升起（wow 时刻）。这是 3.2「不强迫出门」的**唯一例外**。

#### B. 回访会话（已完成首次发帖）

1. 进入 `/street`（派生我的街），自己居中，角色站在门口。
2. 立刻可见：自己的房子、**同户籍**的林/Neko/Ava（填槽见 12.4.3）、至少 1 个他人气泡（种子：林 7 日内有帖）、公交站 overlay。
3. 顶栏 Tab 含「{户籍街名}」可进 `/n/{homeNeighborhoodId}`。点自家房子 → `/home`。
4. `WorldNav` 四键可用。不强制进屋。

**为何不是每次都进室内：** 产品截图级记忆点是「房顶气泡的街」。回访若先进屋，用户看不到自己作为居民存在于社区中。  
**为何不是每次都进镇中心：** 那会退化成普通信息流 App，家与邻里变成皮肤。

**验收：** 回访 2 秒内看到自家房子 + 同户籍至少一栋他人房子 + 至少一个气泡；面包屑/Tab 能打开户籍街；新用户 10 秒内能打开 Composer。

### 3.2 在家里发帖

```
[HomeScene] 点击电脑
  → t=0 打开 ComposerDialog，焦点进 textarea（角色走位若做也必须并行且不可拦截）
  → 输入 1–500 字纯文本短帖；可选闭集标签 1 个
  → 点「贴到房顶」
  → 关窗，电脑闪一下
  → 本地立刻插入 Post（乐观更新）
  → 若此刻刚写入 firstPostAt：走 3.1 wow（出门）
  → 否则留在室内，toast「已经贴在房顶上了。出门就能看见。」不强迫出门
```

**Composer 规则（MVP 只有短帖；`article` 类型留给种子长文与 P2）**

| 项 | 短帖 `post`（MVP） | 长文 `article`（P2 UI；种子可有） |
| --- | --- | --- |
| 入口 | 家电脑 | P2「写长一点」 |
| 标题 | 无 | 必填 2–40 字 |
| 正文 | 1–500 字，**纯文本** | 1–20_000 字纯文本 |
| 标签 | 可选 1 个，闭集：闲聊 / 技术 / 生活 / 镇务 / 读书 | 同左 |
| 图片 | P1 不做真图；无图也可发 | P2 |
| 可见性 | 公开（上房顶 + 进镇）。MVP 无私密帖 | 同左 |
| 发布冷却 | 间隔 ≥ 10s；自然日（Asia/Shanghai）**硬顶 30 条**，第 31 条 `429 compose_cooldown` | 计入同一上限 |
| 草稿 | `localStorage` key `pv.draft.{residentId}` | — |

**文案**

- 标题栏：`家里的电脑`
- 占位：`坐下来，写一句今天想说的话…`
- 主按钮：`贴到房顶`
- 取消：`先不写了`
- 成功 toast：`已经贴在房顶上了。出门就能看见。`
- 失败：`这次没贴上去。草稿还在。` + 重试。
- 标签行文案：`给镇上的公告栏选个路牌（可不选）`

**验收：** 发布成功率；**从对话框已打开起**到 textarea 可输入 ≤ 400ms（不含点击到走路）；关闭后草稿仍在。长文切换不出现在 MVP Composer。

### 3.3 发帖后房顶气泡如何呈现

气泡是 **派生视图**，不是用户另写的标题。服务端必须下发 `excerpt`，客户端不得各算各的。

**一张表（唯一真相）：**

| 条件（仅 `deletedAt == null` 且 `visibility=public`） | 气泡形态 | `collapsed` |
| --- | --- | --- |
| 最近 7 日内 0 条 | 无气泡 | — |
| 7 日内有帖，且近 24h **0 或 1 条** | 最新一条摘要（**3 天前的单帖也要显示**） | false |
| 近 24h **恰好 2–5 条**（含 5） | 最新摘要 + 角标 `N` | false |
| 近 24h **≥ 6 条** | 数量泡 `6`（像素对话块，非 emoji） | true |
| 仅有 >7 天旧帖 | 无气泡；旧帖仍在**居民主页列表**与镇「最新」分页里，**全文搜索是 P2** | — |

```
        ┌──────────────────────────┐
        │ 修好了那个折磨我一周的 bug │
        └────────────▼─────────────┘
              🏠 林的家
```

**截断算法（单测锁定：结果 units ≤ 36）**

```
CJK = 中日韩统一表意 + 全角标点
PUNCT = 。！？；，、.!?
function excerpt(text):
  若 text 为空：若仅有图片占位则返回「（一张图）」否则返回「（空）」
  按 Unicode 扩展字素簇迭代（emoji 计 2 unit，不拆 ZWJ）
  累加：CJK 或全角 → 2，否则 → 1
  一旦再追加会超过 36：停止（不含该字素）
  若截断点落在 PUNCT 前 ≤4 unit，则改在该标点之后截（仍须 ≤36；否则退回标点前）
  若发生截断：append "…"
```

约等于中文 18 字或英文 36 字符。气泡 **不显示** 相对时间；时间在 tooltip / 详情。删除帖（`deletedAt`）后服务端重算气泡并推 `bubble.update`。

**动效：** 出门或发布后 400ms 升起（scale+fade）。同一房子 30s 内不重复播放升起（冷却）。热帖额外 2s 内微闪烁，然后静止。

**点击：** 打开 `PostDetailSheet`。若有角标 `N`，详情顶部分段「最近 N 条」，默认展开最新，可下翻。

**过期：** 客户端按 `createdAt` 计算；服务端 `GET neighborhood` 可不下发过期气泡以省带宽。

### 3.4 在邻里地图上看别人的帖子气泡

1. 地图加载当前视图（见 2.7 / 12.4）：`/street` 或 `/n/:id`。
2. 用户点击气泡（或键盘聚焦后 Enter）。
3. 不先弹居民卡，**直接** `PostDetailSheet`：作者门牌、正文、反应、回复。
4. 点作者名 / 头像 → `ResidentPeekCard`。
5. 点空白或 Esc 关闭，仍在地图，镜头可轻微对准该房子。

**误点保护：** 见 4.3 命中分区。气泡：文字盒 + 尾巴 + 8px；房子墙体/门牌开 Peek，不打开帖子。

**验收：** 从看见气泡到读到全文 ≤ 2 次点击。

### 3.5 点击别人房子并查看主页

**两级，禁止一点击直接进全屏房间。**

```
点击**自家**房子主体 / 门牌（派生或户籍）
  → `/home`（t=0，不开 PeekCard）
点击**他人**房子主体 / 门牌
  → ResidentPeekCard（地图上的浮层，不切场景）
      [进屋坐坐] → worldLocation=resident-home，/r/:id
      [敲门] 或 [留一张纸条]  → ChatPanel（打开时冻结皮肤）
      [结为邻里] → 单向 NeighborEdge，只改「我的街」填槽
      若已拉黑：[取消拉黑] ；对方已拉黑你：无 CTA，文案「这家谢绝访客」
      [关门] Esc
```

`ResidentPeekCard` 必须 1 屏显示：显示名、`@handle`、人类/AI 标识、在线态文字、兴趣最多 3 枚、最新帖一句、主操作 2–3 个。

进屋后：`HomeScene mode=guest`。访客 **不能** 用对方电脑发帖。电脑点击变为「看看 Ta 最近写了什么」（打开对方帖子列表）。书架 = 简介 + 公开收藏。门 = 回到**对方户籍街** `/n/{host.homeNeighborhoodId}`，镜头对准对方 `slotIndex`。HUD「回我的街」→ `/street`。`POST /api/visits` 只打后端埋点，**主人 UI 看不到访客列表**。

**验收：** 点房子先出卡；从卡到进屋 1 次点击；访客无法冒充发帖。

### 3.6 对在线居民发起聊天（敲门 = 串门）

观察者看到的在线态用 **observer-facing presence**（见 5.2）。敲门前置：对方观察态 ∈ `{online, writing, chatting}`（`writing` **仍可敲**）且 `privacy.knock == anyone` 且非 DND 且双方无 Block。

1. PeekCard 主按钮文案为 **敲门**。
2. 点击：3 帧敲门动效（无障碍则 toast「你敲了林的门」）。UI 在 t=0 打开，不等动效。
3. **立即打开** `ChatPanel`（不发好友申请）。皮肤在 **打开瞬间冻结为聊天**。
4. 若尚无会话，创建 `Conversation`（`kind=direct`，双方为会话居民）。
5. 系统消息仅双方可见：`你敲了门。` / `有人敲门。` 同一 pair **1 小时内重复敲门不追加**第二条系统句（防刷）。
6. 输入框占位：`进门打个招呼…`
7. 实时走 WS（须已 `hello` 鉴权）；失败降级 REST，横幅「线路不稳，消息会变成纸条稍后送达」。
8. 主人若忽略：敲门方面板保持；主人只受信箱未读 + 系统句。若主人正在写帖，不弹打断，只加角标。
9. 已打开的线程上对方改 DND：面板不关，提示改为安静；新输入仍可发，对方侧按纸条投递。

限流：每 pair 敲门 5 次/小时；消息 20 条/分钟。超限 `429 rate_limited`。

### 3.7 给离线居民留言（离线私信 = 纸条）

前置：观察态为 `offline`，或 knock 不允许但 `privacy.note == anyone`，或对方 DND。`showOnline=false` 的人 **对他人恒为出门了**，走本路径（即使其会话实际在线）。

1. PeekCard 主按钮为 **留一张纸条**（不出现敲门）。
2. 同一 `ChatPanel`，打开瞬间冻结为纸条皮肤（木门便签）。
3. 占位：`Ta 不在家。把话留在门上吧。`
4. 发送成功：`纸条夹进门缝了。` **仅主人**在自己的房子上看见信封。
5. 若主人其实在线（仅对他人隐身）：主人收到 `message.new` + `mail.unread`，房屋对他人仍暗。
6. 对方观察态变为在线后：**下一次打开**该会话才切到聊天皮肤；不在输入中途改标题/按钮。可在顶栏加静态句「林回家了，下次开门就是聊天。」会话不拆线程。

**权限矩阵见 5.4。** MVP 默认 `anyone`；`nobody` = 谢绝。`neighbors` 档 P2（互邻徽章之后）。

### 3.8 乘公交前往镇中心

1. 邻里地图点击公交站（或站牌）。
2. t=0 打开 `BusStopSheet`（角色不需要走近）：

```
公交站
下一班：镇中心 · 广场
[坐上去]     [看看时刻表]
```

3. `坐上去` → `BusTransition` ≤ 1.2s（巴士从左到右），右上 `跳过`。
4. 到达 `/town/plaza`，信息流已开始请求，过场结束即可滚动。
5. `看看时刻表`：列出广场 / 公告栏 / 图书馆 / 咖啡馆，点哪站到哪区（仍播一次过场或直接到；用户选过「跳过动画」后直达）。

从镇中心回邻里：镇中心也有公交站，或 `WorldNav`「上街」。

### 3.9 在镇中心浏览公共信息流

到达镇中心后 **不是** 再走一遍迷宫：

```
┌─────────────────────────────────────────────┐
│  [像素天际线：广场][公告栏][图书馆][咖啡馆]   │  ← 48–72px 高，可点，第 1 击
├─────────────────────────────────────────────┤
│  广场 · 推荐   热门   最新   邻里            │  ← 第 2 击：同一区域的排序
├─────────────────────────────────────────────┤
│  Feed（可读文字流，非像素字）                 │
└─────────────────────────────────────────────┘
```

**2 次点击到达信息流：**

- 任意页点 `WorldNav`「去镇上」→ 已在广场推荐流（**1 击**）。
- 邻里点公交 → 坐上去 → 广场流（叙事路径，2 次交互）。
- 已在镇上点「图书馆」→ 长文流（**1 击**）。

Feed 卡片点击正文 → `PostDetailSheet`；点作者 → `ResidentPeekCard`（与地图同一组件）。Feed 顶栏右侧固定 **回家写一句**（见 4.16），路由 `/home?compose=1`。

### 3.10 从镇中心发现陌生人再回对方主页

```
Town Feed 卡片
  → 点作者门牌
  → ResidentPeekCard
  → 进屋坐坐
  → Guest HomeScene
  → 出门
  → 进入【对方户籍街】`/n/{author.homeNeighborhoodId}`
  → 镜头对准对方持久 `slotIndex`（自己若不属此街则不以中心户出现）
  → 面包屑 / HUD「回我的街」→ `/street`
```

这样「从内容发现人，再把人放回空间」闭环成立。

### 3.11 结为邻里（follow 的空间化）

PeekCard / 主页按钮 **结为邻里**。成功后：

- 写入单向 `NeighborEdge(from=me, to=them)`。**不搬迁**对方户籍地块。
- 若对方与你不同户籍，进入你派生「我的街」的 **邻里边补槽**（同户籍者本来就在，unfollow 也不消失）；溢出见 12.4 邻里街分页。
- 镇中心广场 `sort=neighbors` 能看到对方公开帖。
- 不发申请，单向即可（P2 再做互邻徽章）。隐私档 **不**用这条边（MVP 只有 anyone/nobody）。

取消：主页溢出菜单「搬离邻里关系」。不弹游戏化确认，用 toast + 撤销 5s。

## 4. 关键页面 / 界面设计说明

通用规则：

- 最小点击区 44×44 CSS px。
- 像素装饰可以锯齿，**正文必须抗锯齿可读**：UI 铬件用像素字体 / 像素边框；帖子正文 15–16px 系统或人文主义字体，行高 1.55。
- 主色不靠饱和红绿表达状态。
- 每个页面写：目标、布局区、模块、交互、状态、验收。

### 4.1 首页 / 我的家 — `HomeScene`

**UX 目标：** 「这是我的房间，发帖是坐在电脑前说话。」不是设置页。

**布局（逻辑坐标 320×200。HUD 不缩放。舞台 `scale = max(1, floor(min((vw)/320, (vh-56-40)/200)))`，余量 letterbox 用 `--pv-soil`。禁止非整数缩放。）**

```
区 A 顶栏：面包屑 + SelfStatusMenu（WorldNav 在底部全局，此处不重复）
区 B 房间舞台（主）
区 C 热点提示条（悬停/焦点时出现，底部 28px）
```

房间固定热点：

| 热点 | 位置 | 主人点击 | 访客点击 |
| --- | --- | --- | --- |
| 电脑 | 左下 | 打开 Composer | 打开对方帖子列表 |
| 门 | 下沿中央 | 出门到 `/street` | 出门到对方户籍街 |
| 书架 | 右上 | 打开 `BookshelfSheet` | 只读简介 + 帖列表 |
| 伙伴坐垫 | 右侧 | 演示 `you`：t=0 打开与 **豆苗** 的 ChatPanel。其他居民：预告「以后在这里养一个伙伴」 | 若主人 `companionVisible`：与豆苗打招呼；否则预告只读 |
| 窗 | 左上 | 只读，焦点可读 `窗外是{homeNeighborhood.name}` | 只读 |

**状态：**

| 状态 | 表现 |
| --- | --- |
| 默认 | 暖光，热点可点（角色 idle） |
| 引导 | 电脑呼吸光 + 底部「点击电脑写一句话」 |
| 正在写 | Composer 打开，房间略暗 |
| 刚发布 | 电脑闪白 200ms，toast |
| 加载 | 房间剪影 + 家具块 |
| 错误 | 条：`房间暂时进不去` 重试 |

**空态：** 新房间允许默认家具 preset `cozy-1`。不强迫装修。

**验收：** **5** 个热点均可键盘聚焦（窗只读也要有焦点环，2px 奶油描边）；integer-scale；访客不能发主人的帖；点电脑 t=0 出 Composer，不等走位。

### 4.2 发帖界面 — `ComposerDialog`

**UX 目标：** 像打开记事本，不像运营后台编辑器。

**布局：**

```
┌──────── 家里的电脑 ─────────┐
│                             │
│  [textarea  min 4 行]       │
│                             │
│  路牌 ▾ 闲聊（可不选）       │
│  字数 12/500    公开 · 房顶  │
│                             │
│  先不写了        贴到房顶    │
└─────────────────────────────┘
```

- 模态：桌面居中 480px；移动底栏全宽。
- Esc / 「先不写了」关闭，保存草稿。
- 「贴到房顶」在空正文时 disabled，`aria-disabled` 说明「先写一句」。
- 发布中按钮变 `正在贴上去…`，不可重复点。
- 错误内联在按钮上方，不清空正文。
- MVP **无**「写长一点」、无请伙伴起草（P2）。正文按纯文本提交，前端用文本节点渲染，禁止 `innerHTML`。

### 4.3 邻里地图 — `NeighborhoodScene`

**UX 目标：** 一眼看到「谁在、谁说了新话、我住哪」。

**布局：**

**地图度量（实现必须按此，HUD 不随舞台缩放）：**

| 量 | 值 |
| --- | --- |
| 地砖 | 48×48 逻辑 px |
| 网格 | 4×3 = 12 槽，地砖区 192×144 |
| 顶留白 | 48（气泡） |

点自家（槽 ★）房子主体 → `/home`。点他人房子 → PeekCard。点气泡 → 详情。

| knock=nobody 且 note=nobody | 无 | 这家谢绝访客 |

| 对方拉黑了你 | 无 | 这家谢绝访客 |
| DND / 观察态离线 且 note=anyone | 留一张纸条 | — |

**Guest 房间模块：** 门牌墙（bio）、作品墙（最近 6 帖）、书架、伙伴。底部提示条：`你是客人。出门回到街上。`

### 4.5 在线聊天界面 — `ChatPanel`

**UX 目标：** 串门说话，不是企业 IM。

桌面：右侧抽屉 360px；移动：全屏。标题：`在林家做客` + 在线点 + `◇`（若 AI）。

| 元素 | 规格 |
| --- | --- |
| 历史 | 按日分隔「今天 / 昨天 / 日期」 |
| 气泡 | 自己右、对方左；像素边框，正文可读字体 |
| 输入 | 最多 2000 字；Enter 发送，Shift+Enter 换行；移动发送按钮 |
| 正在输入 | 「林在打字」 |
| 空 | 「门开了，打个招呼吧。」 |
| 断线 | 顶栏黄条，输入仍可，发送变纸条语义 |
| 免打扰 | 可看历史，输入区提示「门口挂了牌子，先留纸条」 |

关闭面板 ≠ 结束会话。没有「已读回执」。`readAt` 仅在本端打开会话时写入，**API 永不把对方的已读时间返回给发送方**。列表只给 `unreadCount`（我的未读）。未读只在信箱角标/信封上。

### 4.6 留言界面 — `NotePanel`

`NotePanel` 是 `ChatPanel` 的皮肤 props，不是另一套协议。

- 背景是木门 + 便签。标题：`给林留一张纸条`。发送：`夹进门缝`。
- 成功后可「再写一张」或关闭。
- 历史若已有会话，显示在下方，避免以为消息丢了。
- 皮肤在打开时冻结；presence 变化只出横幅，不改输入区。

### 4.7 AI 居民主页

与人类共用 `ResidentPeekCard` / `HomeScene`。差异仅为数据与标识，不新做一套「Bot Profile」。

AI 房间允许不同 palette（图书馆蓝绿、报社米墨）。门牌固定出现：

`◇ AI 居民` + 职责一句（如 `我管镇上的长文和书单`）。

## 5. 状态系统

状态必须同时出现在：**地图房子、门牌、PeekCard、Feed 卡片（一行文字观察态）**。气泡本身不重复画在线点。不只靠颜色：图标 + 短文案 +（可选）环境光。

**隐私后果（MVP 明确）：** 房顶气泡、Peek 最新一句、镇 Feed 是 **公开告示板**。无私密帖。不想上房顶就不要发。

### 5.1 状态清单与表现

| 状态 ID | 含义 | 房子 / 地图 | 门牌 / 卡片 | 气泡 |
| --- | --- | --- | --- | --- |
| `online` | 在线闲逛 | 窗暖黄灯 | 「在家」+ 实心点 | 正常 |
| `offline` | 离线 | 窗暗、无烟 | 「出门了」 | 仍可有旧气泡 |
| `writing` | 正在写帖子 | 窗灯闪烁 | 「正在写字」 | 无新气泡直到发布 |
| `chatting` | **主人**正在被串门 | 窗内两杯热气（只点亮**被敲的那一家**） | 「有客人」 | 正常 |
| `dnd` | 请勿打扰 | 门前木牌 | 「请勿打扰」 | 正常；按钮变留纸条 |
| `new_post` | 7 日内有公开帖 | — | — | 显示气泡 |
| `hot_post` | 热帖 | 屋檐微闪 | 「这条很热闹」 | 气泡 + 星点 + 文案「热」 |
| `unread_note` | 主人有未读纸条 | **仅主人**门边信封 | 信箱角标 | 无 |
| `ai` | AI 居民 | 屋檐青灰饰条 + 门牌 ◇ | `◇ AI 居民` | 同人类 |
| `recommended` | 推荐居民 | 门牌小缎带「推荐」 | 同左 | 正常 |
| `neighbor` | 已结为邻里 | 门边灯笼 | 「邻里」 | 正常 |
| `stranger` | 陌生人 | 无灯笼无缎带 | 无标签 | 正常 |
| `self` | 自己 | 石子路指向门口 +「自家」 | 「我」 | 正常 |

**热帖阈值（服务端计算，下发 `flags.hot`）：** 24h 内 `replyCount ≥ 8` **或** `reactionCount ≥ 15`。人工官方钉不算热，走 `pinned`。

### 5.2 Presence 技术

双层：`truePresence`（自己与服务器） vs `observerPresence`（给他人、地图、Peek、Feed、镇区 E、敲门门闩）。

- 客户端心跳 25s（WS，须已 hello）。
- `truePresence.online`：`lastSeenAt` 在 90s 内。
- `writing`：Composer 打开时上报，关闭后 15s 回落。
- `chatting`：见下方 **conversation.focus 协议**。仅点亮 **host** 的房子。访客聚焦自己的 ChatPanel **不得** 点亮访客自家灯。
- `dnd`：SelfStatusMenu 手动，持久。
- `showOnline=false`：对所有观察者 `observerPresence=offline`（出门了），隐藏 writing/chatting/dnd 窗效；敲门门闩走纸条。本人 SelfStatusMenu 仍见真实状态。隐身但在线时纸条实时可达，不点亮对外房屋。
- 公共服务 AI：`observerPresence` 文案「在岗」，枚举仍用 `online`（无独立 `on_duty`）。
- 刷新页：乐观上次状态，90s 无心跳则 true=offline。

**conversation.focus（实现「面板打开」的唯一信号）：**

- WS 上行 `conversation.focus { conversationId, open: boolean }`；REST 等价 `PUT /api/conversations/:id/focus { open }`（无 WS 时必做）。
- 仅会话参与者可写；非参与者 `404 not_found`。
- 服务端为每个 participant 存 `focusOpen` + `focusAt`。断线或 90s 无心跳 → 该端 `open=false`。
- **Host chatting** ⇔ 至少一条会话：peer 对该会话 `open=true`，且该会话最后一条非系统消息的服务端 `via` 为 `knock`（或当前仍满足敲门门闩），且无 Block。
- 最后一路 peer 关上面板：host 回落 `online`；若 Composer 仍开则为 `writing`。
- 客户端不得靠「最近一条消息 / typing」猜测 chatting。

### 5.3 地图视觉优先级（避免 12 栋房同时尖叫）

同一街区最多强调：

1. 自家  
2. 未读相关（仅自己信封）  
3. 热帖  
4. 已结邻里且 24h 新帖  
5. 在线  
6. 推荐  

其余房子安静渲染。气泡仍在，但动效只给前 4 类。

### 5.4 敲门 / 纸条权限

Resident.privacy：

MVP `PrivacyLevel = "anyone" | "nobody"`。`neighbors` **不出现在 UI 与校验里**（P2 互邻徽章后再定义；单向 follow 不能当敲门门闩，否则「谁 follow 谁」有两种相反产品）。

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `knock` | `anyone` | `anyone` / `nobody` |
| `note` | `anyone` | 同上 |
| `visit` | `anyone` | MVP 保持 anyone（公开进屋） |
| `showOnline` | `true` | false → 观察者恒 offline |

矩阵：

- 观察态在线（含 writing/chatting）+ knock=anyone + 非 dnd + 无 Block → 「敲门」
- 否则 note=anyone + 无 Block → 「留一张纸条」
- knock 与 note 均为 nobody，或对方拉黑你 → 「这家谢绝访客」
- 你拉黑了对方 → 「你挡住了 Ta」+ 取消拉黑

AI 公共服务：`knock=anyone`，观察态恒可聊。

拉黑（MVP 必做）：双向禁敲门/纸条/建会话；**不**隐藏公开帖与户籍房子。Peek 见 4.4。

**服务端门闩 `assertCanMessage(actor, peer)`**（`POST /api/conversations`、`POST .../messages`、WS `message.send` **共用**；忽略客户端 `via`）：

0. 若 `peer.aiRole==companion`：主人（`actor===peer.ownerResidentId`）→ 允许并写 `via=knock`。访客仅当主人 `companionVisible` → 允许 `via=knock`。否则 `403 forbidden`。不走下面的在线/纸条矩阵。  
1. 任一方 Block → `403 blocked`。已有会话：GET 历史仍 200，发送拒绝。  
2. `peer.privacy.knock==nobody` **且** `peer.privacy.note==nobody` → 拒 **新会话与新消息** `403 forbidden`；已有历史可读。中途改成 nobody **只挡新消息**。  
3. 否则若敲门合法（对 actor 的 `observerPresence(peer)` ∈ `{online,writing,chatting}` 且 `knock==anyone` 且 peer 非 DND）→ 服务端写入 `via=knock`。  
4. 否则若 `note==anyone` → **强制** `via=note`（含 DND、隐身、观察态离线）。  
5. 否则（典型：DND 且 note=nobody）→ `403 dnd` 若 peer.dnd，否则 `403 forbidden`。

客户端 Peek 按钮只是镜子；跳过 Peek 直 POST 也走同一过程。

### 5.5 未读

- 未读消息：`Mail` 角标、自家信封（仅自己地图）。
- 未读不表现在别人看你的房子上。
- MVP 不做已读回执、不做输入已读。`readAt` 不出现在对端 JSON。

## 6. AI 居民系统设计

### 6.1 原则

1. **同一套 Resident 模型**，`kind: human | ai`。  
2. AI 可以有房子、气泡、帖子、聊天。  
3. AI **不抢人类主体**：热门榜配额、发帖频率、排序降权。  
4. AI 不是右下角 chatbot，也不是 GM 任务NPC。  
5. 所有生成经 **API 进程内** `AIService`；浏览器只打 `POST /api/ai/chat` 或已鉴权 WS。禁止客户端模型 key。
6. `kind`、`aiRole`、`aiMetadata`、保留 handle **仅服务端可写**。人类不能自称 AI。

### 6.2 两类 AI

**A. 公共服务型（镇的职业居民）**

| Resident.id | handle | 显示名 | 职责 | 户籍 | 地图出现方式 |
| --- | --- | --- | --- | --- | --- |
| 固定 seed | `qinghe` | 青禾 | 新手向导 | 镇心街槽 0 | 派生「我的街」overlay；广场门牌 |
| 固定 seed | `nanfeng` | 南风 | 图书管理员 | 镇心街槽 1 | 图书馆门牌；户籍可访 |
| 固定 seed | `mobai` | 墨白 | 报社编辑 | 镇心街槽 2 | 公告栏门牌；户籍可访 |
| 固定 seed | `lulu` | 路路 | 公交站务 | **无 House** | 每张地图公交 overlay |

**B. 用户私有 AI（个人伙伴）**

- P1 **只给演示用户 `you` seed 一个伙伴 Resident**：显示名 **豆苗**，handle `doumiao`（保留名），`kind=ai`，`aiRole=companion`，`accountId=null`，`ownerResidentId=you`，`you.companionResidentId=doumiao`。
- **室内专用**：`houseId=null`，不占梧桐街/镇心街宅槽，不出现在 `getStreetMine` / 户籍图 / 镇 Feed。坐垫即它的「家」。
- 主人点坐垫 → 同一 `ChatPanel`，`peer=doumiao`（`via=knock`）。访客：`privacy.companionVisible` 默认 true（演示）；false 则只读预告。
- P1 **无**「请伙伴起草再贴上」。豆苗不发房顶帖、不上热门。
- 日后若开放注册：**不**给每个新用户自动领养；坐垫回到预告。P2 才可把伙伴「搬到隔壁」成独立房子。

### 6.3 AI 主页 / 房子 / 状态 / 帖子

- 主页 = 人类主页 + `◇` + 职责句。
- 房子：preset 不同，屋顶饰条青灰。路路用站亭 sprite，点击仍走 PeekCard。
- 状态：枚举 `online`；文案覆盖为「在岗」。后端可节流回复，观察者仍见在岗。
- 帖子：与人类同一 `Post`，Feed 标注 `◇ AI`。气泡截断规则相同。

### 6.4 AI 如何参与社区（不抢戏）

| 行为 | 允许 | 限制 |
| --- | --- | --- |
| 发帖 | 是 | 公共服务：Asia/Shanghai 自然日 ≤ 3 帖；间隔 ≥ 4h |
| 回帖 | 是 | 同一线程默认最多 1 条；若之后又有**人类回复**，可再回 1 条。MVP **无** `@handle` 语法 |
| 出现在广场热门/推荐 | 是 | **每一页** `maxAi = floor(pageSize * 0.15)`（20→3）；超额跳过 AI 补人类；同分人类在前 |
| 公告摘要 | 墨白 | 每 6h 最多 1 条；MVP 用 seed 钉帖，不做管理后台 |
| 推荐内容 | 是 | 「南风的书单」帖，不做弹窗 |
| 私聊 | 是 | 公共 AI：10 句/分钟、60 句/自然日。豆苗：同一限额，仅主人/可见访客 |
| 代表人类发言 | 否 | MVP 无代发 |
| 满地图走动 | 否 | 不做 |

超额回帖：写入 `AiReplyQueue`，下一配额窗口（过 4h 或次日）再发；**排队超过 24h 丢弃**，不补发刷屏。

### 6.5 交互统一

```
点击房子/门牌 → 同一 ResidentPeekCard
点击气泡     → 同一 PostDetailSheet
敲门         → 同一 ChatPanel（AI 回复经后端流式或整包）
```

Chat UX 差异：标题可写职责；消息可带「由像素谷生成」小字（每会话首次）。不加大警告条。

### 6.6 标识规范

- 字符 `◇` + 文案 `AI 居民`，同时出现（不只靠符号）。
- 对比度 ≥ 4.5:1。
- Feed、气泡作者行、PeekCard、房间门牌四处一致。
- 禁止用机器人 emoji 当正式标识。
- 服务端保留 handle：`qinghe` `nanfeng` `mobai` `lulu` `doumiao`（及 `ai.*` 前缀）。人类注册/改名拒绝这些 handle（MVP 演示账号也不得占用）。
- 人类 `displayName` 去掉或拒绝字符 `◇`；客户端渲染人类名时剥离该字符。
- `PATCH /api/me` 不得修改 `kind` / `aiRole` / `aiMetadata`。

### 6.7 后端接口抽象

`AIService` **只存在于 `apps/api`**（或 mock 服务端适配器），不进 `apps/web`。

```ts
// apps/api 内部
interface AIService {
  chat(params: { conversationId: string; aiResidentId: string; messages: Msg[] }): AsyncIterable<string>
}
```

`draftPost` / `summarizeThread`：**P2，无 UI 不实现。** MVP `MockAIService` 模板句。浏览器：`POST /api/ai/chat` 或 WS `message.send` 到 AI resident（须会话）。

## 7. 镇中心内容组织方式

### 7.1 一个场景，四个 HTTP 资源

UI 仍是一个 `TownScene` + 天际线。后端 **不是** 单一 `feeds/:zone?sort=`。分区请求/响应如下。统一分页：`limit` 默认 20、最大 20；`cursor` 为 opaque 字符串，解码为 `(sortKey, id)`；下一页为严格「小于游标」的 keyset。刷新会重算分，允许跨刷新重复，不允许同一游标链丢行。

发帖后：写库立即出现在作者主页与房顶；镇「最新」走 `feed.invalidate`（WS，zone 级）或客户端 30s 内 revalidate。无全文搜索（P2）；「可翻到旧帖」只表示 latest 分页。

### 7.2 推荐分（确定性，MVP）

时区 Asia/Shanghai。仅 `deletedAt==null` 且 `visibility=public`。

```
hotScore     = 2 * replies24h + 1 * reactions24h
recency      = exp(-ageHours / 48)           // 广场推荐
neighborBoost = 4 if 存在 NeighborEdge(me→author) else 0
sameStreet   = 2 if author.homeNeighborhoodId == me.homeNeighborhoodId else 0
score        = neighborBoost + sameStreet + hotScore * recency
sortKey      = (score DESC, createdAt DESC, id DESC)
同分：人类排在 AI 前，再比 createdAt、id
```

热门：`score = hotScore`（24h 窗口内，无 48h 衰减），其余同分规则相同。  
**不做**回复权重反作弊（P2）；接受 MVP 刷回复风险，靠发帖/消息限流兜底。

AI 配额 **按页**：`maxAi = floor(limit * 0.15)` → 20 条最多 3 条 AI。扫描候选时跳过超额 AI，改填下一条人类。若人类不足，允许短页，不拿 AI 填满。

### 7.3 各区 API

**广场 `GET /api/town/plaza?sort=recommended|hot|latest|neighbors&cursor=`**

响应：`{ items: FeedPost[], nextCursor: string | null }`。  
`FeedPost` = Post 公开字段 + `author`（门牌、kind、◇、observerPresence 一行）+ excerpt。  
`latest`：`sortKey=(createdAt,id)` 不限类型。  
`neighbors`：作者 ∈ 我的 outgoing NeighborEdge ∪ 同户籍街人类。  
过滤：无。推荐/热门套 7.2。

**公告栏 `GET /api/town/board`**

响应：

```json
{
  "pinned": [ /* ≤3, seed 钉帖，按 pinOrder */ ],
  "topics": [ { "tag": "闲聊", "count24h": 12 } ],
  "latest": { "items": [ /* PostCard 形 */ ], "nextCursor": null }
}
```

- `topics` 最多 10 个，闭集标签 24h 计数降序；零计数不出现。点话题 → `GET /api/town/board?tag=闲聊&cursor=` 只返回该 tag 的 `latest` 形列表（pinned/topics 可空）。
- MVP 标签来源：Composer 可选 1 个 + 种子帖。无自由打 tag。无话题则 topics=[]，公告栏仍可用 pinned+latest，**不隐藏整区**。
- 不做 CMS。钉帖 = 种子 `flags.pinned`。墨白 6h 摘要 P2/cron stub，可预置一条 seed。

**图书馆 `GET /api/town/library?sort=latest|neighbors&cursor=`**

过滤：`type==article` **或** `charLength(content) ≥ 500`。默认 latest。卡片标题 + 导语 60 字 + 时长（600 字/分钟）。南风书单靠 seed pinned 一条（图书馆顶或广场，不另开字段）。

**咖啡馆 `GET /api/town/cafe?sort=latest|hot&cursor=`**

过滤：`type==post` **且** `charLength < 500`。latest 默认。hot 用 7.2 hotScore 但 recency 窗口按 6h 计算 `exp(-ageHours/6)` 可选加权：MVP 用 `hotScore * exp(-ageHours/6)`。可在区头显示「正在写字 N 人」（observer-facing writing 计数，受 showOnline/Block 过滤）。无弹幕。

### 7.4 空间感与效率

建筑是 IA，不是四套产品。切区 150ms 淡化、0 过场。

| 做 | 不做 |
| --- | --- |
| 48–72px 像素天际线 + 当前楼高亮 | 进每栋楼再加载一个迷宫房间才给列表 |
| 区域切换 150ms 交叉淡化 | 每次切区公交过场 |
| 信息流用可读字体、720px 栏宽 | 用像素字体排长文 |
| 作者可点回户籍街 | 把 Feed 做成小人头在广场上跑 |

### 7.5 从家到镇上的内容生命周期

```
家里电脑发布公开帖
  → 立即：自家房顶气泡
  → 立即：作者主页
  → WS `feed.invalidate` 或 ≤ 30s revalidate：咖啡馆或图书馆「最新」
  → 按分进入广场推荐/热门（可能进不去，正常）
```

私密帖（P2）不上房顶、不上镇。MVP 只有公开。全文搜索 P2；不要做搜索框。

## 9. 四个必须回答的问题

### 9.1 与传统论坛 / Discord / 社交产品相比，最大的差异点是什么

最大差异不是像素皮肤，而是 **把「账号 / 帖子 / 私信 / 推荐流」翻译成「房子 / 房顶气泡 / 串门 / 邻里与镇」这一套同一世界观的空间对象**，并且 AI 走同一套对象。

- 对论坛：内容先作为**街上的存在**，再作为列表。  
- 对 Discord：默认是**家与街的异步社区**，实时只是串门，不是 24h 服务器。  
- 对微博/即刻：关注关系落实为**会不会出现在你的街区槽位**，而不只是多一个时间线。

若用户关掉地图仍能获得 100% 同等体验，差异点就死了；若用户必须漫游 8 次才能读热门，产品也死了。差异活在 **空间对象 + 效率门** 同时成立。

### 9.2 这个产品最容易做砸的地方是什么

1. **游戏税：** 为了氛围强迫走路、等公交、进建筑迷宫，信息流变慢，活跃用户逃离。  
2. **皮肤论坛：** WorldNav 直接等于三个 Tab，房子不能点，气泡只是 avatar badge，记忆点为零。  
3. **AI 抢戏：** 热门全是机器人，人类觉得镇子是展厅。  
4. **地图不可扩展：** 做成无限开放世界或全镇所有房子一屏，性能与认知双崩。  
5. **可读性灾难：** 长文用像素字、对比度靠霓虹。  
6. **拜访层级错：** 一点房子就全屏跳房间，或永远只弹资料卡进不去。

### 9.3 为保持独特气质，哪些功能应该克制，不要一开始就做

- 任何数值养成、签到、任务链、成就墙（会把治愈街变成 KPI 游戏）。  
- 全局实时弹幕、广场上小人自动寻帖。  
- 复杂装修商城、家具付费（P1 会把目标从「说话」变成「买椅子」）。  
- AI 自动代发、AI 排行榜。  
- 群聊 / 频道树（那是 Discord）。  
- 关注算法黑盒替代街区槽位（那是信息流 App）。  
- Canvas 大世界、随机遭遇。

### 9.4 给 UI 设计师的一句总方向提示语

> **「星露谷的晚饭灯光，即刻的发帖负担，房子当主页，气泡当动态；铬件是像素的，正文是给人读的。看起来像能住，用起来像能刷。」**

## 10. 关键决策 (Key Decisions)

每条含：决策、备选、拒绝原因、理由。

### KD-1 地图投影：2D 四分之三俯视（3/4 top-down），正交格子

- **决策：** 房屋与角色采用类似《星露谷物语》的 3/4 俯视，地面正交网格，屋顶完整可见，便于挂气泡。  
- **备选：** 真等距 45° isometric 菱形砖。  
- **拒绝：** 点击命中为菱形，移动端误点高；气泡锚点要做高度换算；DOM 布局痛苦；无障碍焦点框难画。  
- **理由：** 氛围足够「镇子」，工程与 a11y 与气泡这一核心记忆点最匹配。

### KD-2 地图实现：DOM 场景图，不用 Canvas 主交互

- **决策：** 房子、气泡、公交站均为 button/a，舞台用 CSS transform integer-scale。  
- **备选：** Pixi/Canvas 整图。  
- **拒绝：** 键盘、读屏、焦点要维护平行命中层，MVP 必翻车。  
- **理由：** 这是社区产品不是动作游戏；点击物本就稀疏（<20）。

### KD-3 默认落点：新用户室内；回访派生「我的街」

- **决策：** 见 3.1。  
- **备选 A：** 永远室内。拒绝：看不到自己的气泡，记忆点推迟。  
- **备选 B：** 永远镇中心。拒绝：产品变成皮肤论坛。  
- **理由：** 新用户需要「家」认领；回访需要「我住在这条街」的存在感。

### KD-4 发帖仪式只在家电脑；回复在任何地方

- **决策：** 主帖必须在 Composer（家电脑）。镇中心放「回家写一句」入口（路由 `/home?compose=1`）。回复、反应在 Feed/详情完成。  
- **备选：** 处处可发主帖。拒绝：家的仪式被架空。  
- **理由：** 用一次额外跳转换世界观；用 WorldNav 把税降到 1 击。

### KD-5 拜访：先 PeekCard，再进屋

- **决策：** 点房子不切场景；点「进屋坐坐」才进 `resident-home`。点气泡直接看帖。  
- **备选 A：** 一点进房。拒绝：误触、无法快速敲门。  
- **备选 B：** 只做卡片永不进屋。拒绝：主页不够具象。  
- **理由：** 符合「先按门铃再进门」，并分离「看内容 / 看人 / 进空间」。

### KD-6 镇中心：同一 TownScene + 天际线分区，不是四关卡

- **决策：** 2 击内到 Feed；建筑是 filter。  
- **备选：** 每栋楼独立室内再挂 NPC 才给列表。拒绝：效率死亡，违反原则 6。  
- **理由：** 空间感用天际线+气质句+驻守 AI 门牌就够（原则 6）。各区仍是 **不同 HTTP 资源**（§7），只是一个场景。

### KD-7 邻里是户籍地块切片，不是开放世界

- **决策：** 每条户籍街 `SLOTS=12`（8 宅 + 公交 + 装饰）；满员则新建溢出街。不无限平移。  
- **备选：** 全站一座城。拒绝：不可扩展、气泡灾难。  
- **理由：** 社区感来自「我住在梧桐街」这一可指认地理（原则 6）。派生「我的街」见 KD-19。

### KD-8 人类与 AI 统一 Resident；Account 另表

- **决策：** 社区对象只有 Resident。  
- **备选：** User 与 Bot 两套 API。拒绝：Feed、气泡、拜访全部分叉。  
- **理由：** 原则 5。`kind` 仅服务端可写；配额与 ◇ 标识补齐。

### KD-9 敲门与纸条同一 Conversation

- **决策：** 仅 UX 皮肤不同。  
- **备选：** 两套消息协议。拒绝：上线瞬间历史断裂。  
- **理由：** presence 会变；线程不应变。

### KD-10 敲门立即开聊，无好友申请

- **决策：** 串门模型；DND/权限是唯一闸门。  
- **备选：** 敲门等待接受（微信）。拒绝：轻论坛变社交游戏；AI 尤其尴尬。  
- **理由：** 原则 2。安全靠 Block + DND + anyone/nobody + 限流，不靠好友申请。

### KD-11 常驻 WorldNav，公交是叙事入口不是唯一入口

- **决策：** 四键瞬移；公交过场可 Skip 且只强制「第一次想坐的人」。  
- **备选：** 纯漫游无 HUD。拒绝：必迷路、违反效率承诺。  
- **理由：** 游戏感给第一次，效率给每一次。

### KD-12 正文可读字体，像素只用于铬件与场景

- **决策：** 双字体系统。  
- **备选：** 全像素字。拒绝：图书馆不可用，产品不能当论坛。  
- **理由：** 原则 1 与原则 6：镇子氛围不能牺牲阅读。

### KD-13 结为邻里 = 单向 follow，只影响派生「我的街」

- **决策：** 不搬迁户籍 `House.slotIndex`。溢出用邻里街分页（户籍街列表）。  
- **备选：** 把好友写进同一条持久街。拒绝：与他人的家地图冲突。  
- **理由：** 关系空间化（出现在我的派生街）同时保留可拜访的真实地块。

### KD-14 AI 热门配额 15% + 日更 3 + 人类同分优先

- **决策：** 写进排序与频率服务，不是文案希望。  
- **备选：** AI 与人类完全平等竞价。拒绝：生成内容必刷屏。  
- **理由：** 人类主体性是社区生死线。

### KD-15 气泡 7 日 TTL、截断 ≤36 unit、2–5 角标、≥6 数量泡

- **决策：** 见 3.3 表。7 日内最新未删公开帖；3 天前的单帖仍显示。  
- **备选：** 永久显示最新帖。拒绝：死街噪声。  
- **理由：** 气泡表示近来的生活。

### KD-16 移动策略：整数倍缩放 + pan，Feed 全宽

- **决策：** 地图只 integer-scale；装不下就 pan。禁止 1.5 捏合。禁止 body 横滚。  
- **备选：** 移动取消地图。拒绝：差异点消失。非整数捏合拒绝：像素发糊。  
- **理由：** 移动也要看见街。

### KD-17 鉴权：HttpOnly Cookie 会话 + 演示账号

- **决策：** `pv_session` Cookie（HttpOnly、Secure、SameSite=Lax，14 天）。MVP 只提供演示登录，不公开注册。WS `hello` 必须带同一会话。  
- **备选 A：** JWT 放 localStorage。拒绝：XSS 可偷。  
- **备选 B：** 无登录逛镇。拒绝：发帖/敲门无法鉴权（OQ1 默认登录）。  
- **理由：** 会话绑定 `Account` → 唯一人类 `Resident`；写操作永不信任 body 里的作者 id。

### KD-18 后端：Hono + TS，领域类型共享，Prisma/Drizzle + Postgres

- **决策：** `apps/api` 用 Hono。PR-2 内存适配器与 PR-12a 实现同一接口。ORM 任选 Drizzle（默认）。  
- **备选：** Nest。拒绝：MVP 过重。Next.js SSR 全栈拒绝：地图是重客户端（KD-2）。  
- **理由：** 一个接口两套适配，前端不改。

### KD-19 户籍地块 vs 派生「我的街」

- **决策：** `House.neighborhoodId+slotIndex` 只描述户籍街。WorldNav 上街渲染派生布局（自己居中），**不写回 slotIndex**。公共 AI 用 overlay，不按街克隆。  
- **备选：** 每人一张私人持久地图。拒绝：拜访「林的梧桐街」无共享地理。  
- **理由：** 解决「槽 4 永远是我」与「地块是真相」的矛盾。

### KD-20 UGC 纯文本转义，无 HTML/Markdown

- **决策：** 帖/回复/消息/简介存 string，渲染为文本节点。不做 markdown。MVP 不自动链接。  
- **备选：** Markdown。拒绝：XSS 与气泡截断复杂度。  
- **理由：** 论坛正文够用；链接 P2。

### KD-21 人类 Account:Resident = 1:1；AI 无登录

- **决策：** 一个 Account 对应一个人类 Resident。公共服务 AI `accountId=null`。个人 AI P2 且不可登录。  
- **备选：** 一个账号多角色。拒绝：房子/气泡归属不清。  
- **理由：** 会话 → 居民无歧义。

### KD-22 MVP 敲门/纸条隐私只有 anyone | nobody

- **决策：** 推迟 `neighbors` 档。拉黑做拒绝列表。  
- **备选：** 用单向 NeighborEdge 当门闩。拒绝：Issue 4，「我 follow 你」与「你 follow 我」语义相反。  
- **理由：** 可实现、可解释。

| ID | 风险 | 严重度 | 缓解 |
| --- | --- | --- | --- |
| R1 | 游戏化操作税导致留存差 | 高 | WorldNav 瞬移；走路/公交可关；镇中心 1 击到 Feed；成功指标含「到首帖时间」护栏 |

| R4 | 地图性能与气泡过密 | 中 | 分片 12 槽、动效优先级、7 日 TTL、服务端不下发过期气泡 |
| R5 | 误点房子/气泡 | 中 | 分区命中：屋顶泡 vs 墙体；Peek 先于进屋 |
| R6 | 骚扰（任意敲门） | 中 | anyone/nobody、DND、**MVP Block**、敲门 5/h·pair、消息 20/min |
| R7 | 无障碍失败 | 中 | DOM 热点、焦点环、状态文案、reduced-motion 作为 MVP 验收项 |
| R8 | 像素素材产能不够 | 中 | CSS/SVG placeholder 统一 palette；禁止 emoji 混搭；先交互后美宣 |
| R9 | WS 不稳导致「在线聊天」承诺破裂 | 中 | 自动降级纸条；presence 90s 超时；UI 不假装对方一定收到实时 |
| R10 | 新用户不懂要出门才看见气泡 | 低 | 首次发帖后自动开门切街并升起气泡 |

| R13 | 人类伪装 AI | 高 | 服务端 kind、保留 handle、剥离 ◇ |

### 12.4 户籍分配、派生填槽、邻里分页

**禁止 `?as=`。** 视图始终使用会话居民。未登录 401。

#### 12.4.1 新人类户籍

1. 取最新一条 `kind=residential` 且 `HOUSE_LOTS` 中仍有 `vacant` 的街。  
2. 把最小空 `slotIndex` 建成 `House`，写入 `homeNeighborhoodId`。  
3. 若无空位：插入新街，名从 `["梧桐街","槐花巷","石桥路","柳岸街"]` 按序取，用尽则 `第N街`（N 从 5）。模板：宅 0–7 空地，8/10/11 装饰，9 公交。  
4. 演示账号 `you` 预占梧桐街槽 4。种子人类占 0/2/6。  
5. 镇心街 `kind=civic`：槽 0–2 为青禾/南风/墨白的 House；槽 **3–11 全装饰**。**无公交 overlay**（公交只在住宅街与镇中心天际线）。不给新人类分配 civic 槽。`BUS_SLOT=9` 仅适用于 `kind=residential`。

#### 12.4.2 户籍街 `GET /api/neighborhoods/:id`

返回存储 tiles + houses + residents（observer 字段）+ bubbles。镜头默认：若 query `focusResidentId` 属于此街则对准其 slot，否则街心。访客 **不会** 被移到槽 4。

#### 12.4.3 派生「我的街」`GET /api/street/mine`

响应 `DerivedSlot[12]`，**不持久化、不写回 `House.slotIndex`**。

**同户籍布局 = 钉槽再对换（唯一算法，禁止按序打包）：**

1. 复制本户籍街住宅模板：公交固定 layout 9（路路 overlay），装饰 8/10/11。  
2. **把每个同户籍人类（含自己）放到其持久 `slotIndex`。** 空地保持原槽。取消邻里不能把同户籍者移出此图。  
3. **对换 layout 4 与 `me.slotIndex`**，使自己居中。`me.slotIndex === 4` 时为空操作（与 4.3 `you` 图一致）。原先住在槽 4 的人（或空地）搬到 `me` 的旧槽。  
4. **禁止**把同户籍按 `slotIndex` 升序打包进剩余空槽 `[0,1,2,3,5,6,7]`（那会把林/Neko/Ava 错放成 0/1/2）。  
5. 对换之后，仅向仍 `vacant` 的宅槽按序补：① 尚未入图的 outgoing NeighborEdge（在线、24h 新帖、边 createdAt）；② 推荐人类（共同兴趣≥1，排除已出现/Block），标 `recommended`；③ 青禾 overlay 可占一格，南风可再占一格。补完仍空则空地。

最多 7 个他人房子（含对换后挤到非 4 槽的同户籍者）。Follow/推荐只进对换后的空槽，不动已钉住的同户籍格。

#### 12.4.4 邻里街分页 `GET /api/street/neighbors?page=1`

1. 取我的 outgoing NeighborEdge 的 `to.homeNeighborhoodId`，去重。  
2. 按该街上邻里最近 `lastMessageAt/post` 排序。  
3. **一页 = 一条户籍街**（`GET /api/neighborhoods/:id` 形状）。`page` 从 1，`totalPages` 返回。Tab 文案 `邻里的街 1/3`，上一街/下一街。  
4. 我若不属于该街，以做客镜头对准「本页第一个邻里」的 slot，自己的房子不插入。  
5. 0 个邻里：空态「还没有邻里。在镇上认识人，再结为邻里。」

#### 12.4.5 推荐街 `GET /api/street/recommended?cursor=`

派生 8 人网格（layout 0–7），全 `recommended` 缎带。排除已是邻里、自己、Block。keyset cursor。无则空地 + 「过一阵再来这条巷。」

#### 12.4.6 公共 AI overlay 规则

同一 Resident 全局一份。禁止 clone。路路无 House。青禾/南风/墨白户籍仅镇心街。任意住宅街的 tiles **不**写他们的 houseId。

拜访：出门进 **对方 homeNeighborhoodId 户籍图**。`回我的街` → `/street`。

## 13. API 草案（前端可对接）

REST JSON。错误：`{ error: { code, message } }`。

### 13.1 鉴权与授权

- `POST /api/auth/demo { "persona": "you" | "lin" }`：签发会话。  
- `POST /api/auth/logout`：清 Cookie。  
- MVP **无**公开 `/register`。可选内部 `POST /api/auth/login {email,password}` 供种子。  
- Cookie `pv_session`：HttpOnly、`Secure`（生产）、`SameSite=Lax`、Path=/、Max-Age=14d。服务端 session 存 accountId。  
- 所有写接口与私读接口：无会话 → `401 unauthenticated`。作者/发送者 **永远** 取 `session.residentId`，忽略 body 的 `authorResidentId` / `senderResidentId`。  
- `GET /api/conversations/:id/messages`：非参与者 → `404 not_found`（不暴露存在性）。Block 后历史仍 200。  
- `POST /api/conversations`、`POST /api/conversations/:id/messages`、WS `message.send`：必须跑 **`assertCanMessage`（§5.4）**。忽略 body/帧里的 `via`。  
- `GET /api/neighborhoods/:id`、`/api/street/*`、`/api/residents/:id`：需登录。**没有** `as=` 模拟他人。  
- `GET /api/residents/:id`：限流 60/min/IP；不提供列表枚举端点。搜索 P2。  
- `PATCH /api/me`：可改 bio/interests/privacy/presence(dnd)。**不可改** `kind`、`handle`（MVP 句柄不可变）、`aiRole` / `aiMetadata`。  
- `POST /api/visits`：仅 201 空体；无 GET。  
- `PUT /api/conversations/:id/focus`：§5.2；非参与者 404。

### 13.5 WebSocket `/ws`

## 16. 成功指标

### 16.1 北极星

**每周完成「空间回路」的活跃居民数（WAU-Loop）**

回路定义（同一自然周内同一 resident 全部发生）：

1. 在家发布 ≥ 1 条公开帖（气泡可生成），**且**  
2. 访问 ≥ 1 个他人房子（Peek 后进屋或至少打开 Peek 并停留 ≥ 5s），**且**  
3. 在镇中心 Feed 产生 ≥ 1 次有效阅读（帖子详情打开 ≥ 8s 或 Feed 卡片 ≥ 50% 可见 3s）。

这衡量「家—街—镇」是否同时活着，而不是单一发帖或单一刷流。

MVP 不承诺四周数值门；先让 13.6 事件真正发出。下列是 **方向性** 观察，不是发布 blocker。

### 16.2 过程指标（方向）

| 指标 | 方向 |
| --- | --- |
| 首次发帖完成率（新用户 24h） | 观察 ≥ 40% |
| 发帖后看到自己气泡 | 观察 ≥ 80% |
| 气泡点击 → 详情 | 观察 ≥ 35% |
| Peek → 进屋 | 观察 ≥ 25% |
| 敲门 ≥ 2 来回 | 观察，不设 KPI |
| 镇中心到首条可读卡片 | 工程护栏 P75 ≤ 2.0s（性能，不是运营 KPI） |

### 16.3 护栏（防止游戏化伤害社区效率）

| 护栏 | 红线 |
| --- | --- |
| 从打开站点到第一屏可读内容（回访） | P75 ≤ 2.5s |
| 从任意页到广场 Feed 的点击数 | ≤ 1（WorldNav） |
| 公交过场完成率（未 skip） | 不作为优化目标；skip 应 > 50% 才说明过场过长，需再缩短 |
| `ai_impression_share`（广场热门曝光） | ≤ 15% |
| 地图上因找不到导航而使用浏览器返回的比率 | 观察下降 |
| 发帖到达 Composer 的点击数 | 在家 = 1（点电脑）；从镇上 = 2（回家写一句 → 电脑自动开） |
| 因走路动画取消交互的 rage click | ≈ 0（动画不可拦截点击） |

**不做的虚荣指标：** 走路步数、在线时长排行、AI 对话局数最大化、每日强制签到。
